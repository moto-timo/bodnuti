**review:** With a `[review]` table in `watch.toml`, `bodnuti poll` sends each checked patch, with context gathered in the check container, to an OpenAI-compatible endpoint serving an open-weight model, and keeps the validated findings apart from the checks' results. `guides` adds sashiko's Yocto review guides, its false-positive guide and severity scale to each request, and with `docs` (or `check --review-docs`) a request also carries the Yocto and BitBake documentation of the task flags, classes and variables the patch changes, and the value bitbake.conf gives each of those variables. With `verify = true`, each finding is checked once more by the model, with the built-in review rules its patch's files and lines select (a `rules/` directory in `guides` replaces them) and read-only git tools, and shown only if confirmed with a quote from the patch, its context or a tool (draft). With `escalation_model` set, a patch that touches classes, meta/lib/oe or bitbake.conf, fixes a CVE, or gets a low-confidence review goes to a larger model with the same rules and tools (draft). Each poll then scores the reviews against what the lists decided: findings near lines a later revision changed, or in files a later Fixes: commit changed, count as confirmed, by month and configuration in state/review/outcomes/ (draft). `min_confidence` (default medium) drops findings the model rates lower; `reasoning_effort` and `thinking` steer a reasoning model, `max_tokens` gives one that reasons at length more room, and `retry_effort` sets the effort of the retry after a model reasons until max_tokens (default none; gpt-oss wants low). When the endpoint gives no answer for two patches in a row (no connection, a timeout, HTTP 5xx), or none during the check pass, review stops for that run instead of waiting the full timeout on every patch; queued patches wait for the next poll. `samples` asks layer 3 that many times and merges the findings, and shows a finding only when most of the check pass's answers confirm it, since a local model does not answer the same request the same way twice. A request that would not fit `context_tokens` with `max_tokens` leaves out the context it needs least, logging each item, instead of filling the model's context. Requests no longer force temperature 0: the model's own sampling setting applies unless `temperature` is set, since reasoning models such as Qwen and gemma loop under greedy decoding.
